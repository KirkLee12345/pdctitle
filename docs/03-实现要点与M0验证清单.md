# 03 · 实现要点与 M0 验证清单（26.2 专属，v3）

> 26.x 起游戏**不再混淆**（无 Yarn、无 remap），开发用 Mojang 官方映射（unobfuscated）。
> 官方示例：`FabricMC/fabric-example-mod` 分支 `26.2`
> （Loom `1.17-SNAPSHOT`、Gradle 9.5.1、Java 25、Loader `0.19.5`）。
> 反编译源核对：**mcsrc.dev**（Mojang 官方 26.2 源码）。

## 1. 开发环境（必须）

- JDK **25**（Gradle JVM 也须 ≥25）；项目自带 Gradle Wrapper 9.5.1：`./gradlew build`；
- IDE：IntelliJ IDEA 2025.3+（Mixin 注解兼容）。

## 2. 钩子清单（Mixin 目标，M0 逐一验证）

| # | 目标功能 | 目标类/方法（Mojang 名，以 26.2 实测为准） | 策略 |
|---|---|---|---|
| H1 | 头顶名牌 Team | `net.minecraft.world.scores`：`ServerScoreboard`/`PlayerTeam`，`setPlayerPrefix(Component)`、建队/入队 | 佩戴→进队设前缀；卸下/无→移出；JOIN/重生重断言 |
| H2a | Tab 显示名来源 | `ServerPlayer#getTabListDisplayName()`（查 mcsrc.dev 确认是否存在/改名） | @Inject 返回 佩戴称号+名字 或原逻辑 |
| H2b | Tab 主动刷新 | `ClientboundPlayerInfoUpdatePacket(Action.UPDATE_DISPLAY_NAME, entry)` 广播给全体在线 | 变更后广播；JOIN 对新玩家兜底 |
| H3 | 聊天拦截重发 | 聊天广播入口（`PlayerList#broadcastChatMessage(...)`? 26.2 确认） | 取消原签名消息→`broadcastSystemMessage` 重发自组装行 |
| H4 | JOIN/重生钩子 | `PlayerList#placeNewPlayer(...)` / 重生路径（26.2 确认） | 幂等执行 H1+H2b |
| H5 | 命令注册（无 fabric-api） | `net.minecraft.commands.CommandDispatcher` 构造器 @Inject at TAIL | 调 `TitleCommands.register` |

回退：若某处 Mixin 在 26.2 不稳，可临时引入 fabric-api（`ServerMessageEvents` / `ServerPlayConnectionEvents` /
`CommandRegistrationCallback`）——本项目最终未采用，纯 Mixin 实现（零 fabric-api 依赖）。

实现中的两个关键踩坑（均已落地）：
1. 玩家聊天还存在第二层出口 `ServerGamePacketListenerImpl#sendPlayerChatMessage`（PlayerChatSendMixin 兜底）；
   第三方验证/离线服的“未签名”消息会被标为 `isSystem()==true`，漏斗拦截**不能**以 isSystem 放行，否则会漏拦截；
2. `add` 的显示文案使用内置 `string()` 参数：含 `&`/`[]`/中文/空格时需英文双引号包裹。
   （曾尝试自定义 ArgumentType，但 26.2 命令参数类型需注册进 `ArgumentTypeInfos`，未注册会导致玩家进服崩溃，已弃用。）

## 3. 聊天重发 + 悬停描述要点

1. **只拦截佩戴了称号的玩家**；其余走原版链路；
2. 重发用系统消息通道（overlay=false）→ 无 “Not Secure/已修改” 徽标；
3. 悬停组件：
   - “称号”块 = 解析 `&` 颜色码后的 display 文本组件，setStyle 挂 `HoverEvent(SHOW_TEXT, …)`；
   - 悬停文本 = `称号显示名\n描述(灰色 italic)`（无描述时只有称号名行）；样式仿成就/进度提示；
   - 组件结构：`titleChunk(hover).append(" ").append(nameChunk)`，悬停只触发在称号字上；
4. `/msg`、`/say` 等命令消息不走玩家聊天拦截（不在本次范围）；与其他聊天 mod 防双发；
5. 聊天栏悬停由服务端组件实现，**原版客户端即可显示**。

## 4. 数据层边界用例（纯 JUnit，M1）

- 池：add 覆盖同 id、desc 清空、remove 级联返回受影响 UUID、remove 不存在 id 幂等；
- 玩家：grant 同 id 幂等拒绝、revoke 佩戴中自动卸下、wear 未授权拒绝、clear；
- 加载容错：坏 JSON / 缺文件 / owned 指向不存在的 id（自动清理）/ equipped 指向未拥有 id（置空）；
- 文本清洗：换行/控制符剥除、超长截断、中文正常。

## 5. M0 探针验证清单（先跑通再全量实现）

1. 最小可编译工程 + 空 @Mixin 类（验证 loader/mixin 生效）；
2. H1：手动建队 setPrefix → 原版客户端头顶即时显示；
3. H2a：Mixin getTabListDisplayName → 新进服玩家 Tab 带自定义名；
4. H2b：构造 UPDATE_DISPLAY_NAME 广播 → 在线玩家 Tab 即时刷新；
5. H3：确认 26.2 聊天广播真实入口（mcsrc.dev），原型“拦截 + 系统消息重发”，检查显示效果与徽标；
6. H3.5：重发行的称号块挂 HoverEvent → **鼠标悬停显示称号名+描述**（原版客户端验收）；
7. H5：CommandDispatcher 注入成功、最小命令可执行；
8. 验收：H1/H2/H3/H3.5 全部通过后进入 M2/M3。

## 6. 备选：客户端混合方案（暂不实施，留档）

需要保留完整签名聊天时：服务端存权威数据，客户端 Companion 模组本地渲染聊天前缀（含描述可另做本地 tooltip）。
部署成本高（全员装客户端），本需求不采用。

## 7. 风险与注意

- 26.2 生态新，类名可能异于 1.21 时代，一律以 mcsrc.dev 实测为准；
- 升级 26.3+：先重跑 M0，主要成本在 H3；
- 全项目 UTF-8（中文文案/日志/文档）。
