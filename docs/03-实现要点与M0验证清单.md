# 03 · 实现要点与 M0 验证清单（26.2 专属）

> 26.x 起游戏**不再混淆**（无 Yarn、无 remap），开发用 Mojang 官方映射（unobfuscated）。
> 代码参考 26.2 官方示例：`FabricMC/fabric-example-mod` 分支 `26.2`
> （Loom `1.17-SNAPSHOT`、Gradle 9.5.1、Java 25、Loader `0.19.5`）。
> 反编译源核对工具：**mcsrc.dev**（Mojang 官方 26.2 源码在线查看）。

## 1. 开发环境（必须）

- JDK **25**（Gradle JVM 也须 ≥25）；
- 项目自带 Gradle Wrapper（9.5.1），无需本机安装 Gradle：
  `./gradlew build`；
- IDE：IntelliJ IDEA 2025.3+（Mixin 注解处理兼容性要求）。

## 2. 三个钩子（Mixin 目标，M0 逐一验证）

| # | 目标功能 | 目标类 / 方法（Mojang 名，**以 26.2 实测为准**） | 实现策略 |
|---|---|---|---|
| H1 | 头顶名牌 Team | `net.minecraft.world.scores` 的 `ServerScoreboard` / `PlayerTeam`：`setPlayerPrefix(Component)`、`addPlayerToTeam(String,...)`、按名字建队 | 佩戴→进队+设前缀；卸下→出队；JOIN/重生重断言 |
| H2a | Tab 显示名来源 | `ServerPlayer#getTabListDisplayName()`（可能改名，需查 mcsrc.dev） | @Inject 返回 `佩戴称号+名字` 或原逻辑 |
| H2b | Tab 主动刷新 | `ClientboundPlayerInfoUpdatePacket(Action.UPDATE_DISPLAY_NAME, entry)`，发送给全体在线玩家 | 变更后广播；JOIN 时对新玩家兜底补发 |
| H3 | 聊天拦截重发 | 聊天广播入口（`PlayerList#broadcastChatMessage(...)`？26.2 确认） | 取消原签名消息 → `broadcastSystemMessage` 自组装行 |
| H4 | JOIN / 重生钩子 | `PlayerList#placeNewPlayer(...)` / 重生路径（26.2 确认） | 幂等地执行 H1+H2b |
| H5 | 命令注册（无 fabric-api） | `net.minecraft.commands.CommandDispatcher` 构造器 @Inject at TAIL | 拿到 dispatcher 后调 `TitleCommands.register` |

> 若 H5 在 26.2 难以稳定注入，备选：依赖 fabric-api 的
> `CommandRegistrationCallback`（需要改 build.gradle 加一行依赖，其余逻辑不变）。
> 同理 H3/H4 也有 fabric-api 事件回退（`ServerMessageEvents`、`ServerPlayConnectionEvents`）。

## 3. 聊天重发的正确性要点

1. **只拦截“有佩戴称号的玩家”的聊天**；无称号者完全走原版链路；
2. 重发使用系统消息通道（`overlay=false`，进聊天栏、非标题），不产生 “Not Secure/已修改” 徽标；
3. 注意 `/msg`、`/say` 等命令消息**不**走玩家聊天拦截（不在本次范围）；
4. 若服上还有别的聊天模组，防双发：重发前检查消息来源是否为已被我们替换过的行，或保留总开关；
5. 中文/全角字符无特殊处理需求，`Component` 原生支持。

## 4. 与数据/其它系统的关系

- 玩家改名：全程按 UUID，无影响；
- 别的玩法占用队伍：进队前 `scoreboard.getPlayersTeam(name)` 检查，被占用则：把对方 prefix 并入前缀，
  或仅日志告警并跳过名牌（**私服默认告警跳过，文档说明**）；
- 击杀消息/死亡消息/进度消息显示的玩家名：是否带称号属于**扩展**（默认不带），避免副作用。

## 5. M0 探针验证清单（写代码前必须先跑通，逐项在 26.2 实测）

1. 搭出最小可编译工程（本骨架 + 一个空 `@Mixin` 类验证 loader/mixin 生效）；
2. H1：手动建队设 prefix → 确认**所有原版客户端**头顶即时显示；
3. H2a：Mixin `getTabListDisplayName` 后新进服玩家看到的 Tab 是否带自定义名；
4. H2b：构造 UPDATE_DISPLAY_NAME 包广播 → 在线玩家 Tab 即时刷新；
5. H3：在 26.2 找到聊天广播真实入口与签名（mcsrc.dev），用“拦截+系统消息重发”做原型，
   确认显示效果、徽标情况、`/msg` 等不受影响；
6. H5：确认命令可注入，权限回调可用的最小命令可执行；
7. 验收数据（H1/H2/H3）三处同时生效后再进入 M2/M3 全量实现。

## 6. 备选：客户端混合方案（暂不实施，留档）

服务端保留“权威称号数据”；每个客户端装 Companion 模组，聊天行渲染时本地在发送者名前加前缀，
从而保留原版签名聊天的全部特性。部署成本：全员装客户端。需要时再评估。

## 7. 风险与注意

- 26.2 是稳定版但仍是“新版生态”，部分类名与 1.21 时代不同，务必以 mcsrc.dev 实测为准；
- 升级 26.3+：先跑 M0 清单再合并，主要成本在 H3 聊天入口；
- 编码：全项目 UTF-8（中文文案/日志），build 产物无需额外处理。
